What this converts
Kibana dashboards (.ndjson) — Lens incl. formulas, TSVB, legacy visualizations, saved searches, controls, Vega with an embedded ES query → Dynatrace dashboard JSON — DQL tiles, variables, series colours; importable in the Dashboards app
ES|QL · Query DSL · KQL · Lucene → DQL, linted offline before it reaches you
Logstash (.conf) · Elasticsearch ingest pipelines → OpenPipeline stages — readable .dpl plus a deployable Terraform module
Watchers · Kibana alerting rules (incl. index-threshold and ES-query rules) → Davis anomaly detectors + Workflows, as Terraform
Continuous transforms → Rollup DQL with a migration note per transform
ILM policies · index templates · enrich policies → Written guides — bucket retention, OpenPipeline routing, Grail lookups

Every run also writes MIGRATION_REPORT.md, a field manifest per dashboard (*.fields.md), METRICS-GUIDE.md for log→metric extraction, and a suggested mapping.config.json when your index patterns need rules.

Caveats
  • Maps and truly-custom Vega panels become placeholder tiles flagged MANUAL — rebuild those by hand in Dynatrace.
  • Lens formulas with no DQL equivalent fall back to a flagged count() placeholder; nothing is ever converted silently wrong.
  • A converted tile renders empty — with no error — when a custom field it queries isn't ingested in Dynatrace. Check each dashboard's .fields.md manifest before trusting a blank chart.
  • Index patterns without a mapping rule default to logs; review the suggested mapping.config.json and re-run to make routing explicit.
  • Alert thresholds and evaluation windows are best-effort — review each anomaly detector before enabling it in production.
  • Canvas workpads, ML jobs and SLOs have no converter. Unrecognised files are listed as skipped, with a reason — never silently dropped.

Powered by the e2d engine compiled to WebAssembly (Pyodide). Conversion, DQL linting, field audits and the migration report all run locally in this tab — this page makes no network requests with your data.
