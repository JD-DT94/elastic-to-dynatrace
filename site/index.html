What it converts, and limits

This page runs entirely in your browser and never connects to anything: it converts, scores and lets you tune. The connected steps (live pull, backfill, verify, deploy) need the local tool: pip install git+https://github.com/JD-DT94/elastic-to-dynatrace then e2d web.

Kibana dashboards

Lens incl. formulas, TSVB, legacy visualizations, saved searches, controls, Vega with an embedded ES query → dashboard JSON with DQL tiles, variables and series colours. Import in the Dashboards app.

Queries

ES|QL, Query DSL, KQL and Lucene → DQL, linted offline before it reaches you.

Ingest pipelines

Logstash .conf and Elasticsearch ingest pipelines → OpenPipeline stages: a readable .dpl plus your choice of upload-ready Settings JSON or a Terraform module.

Alerts & watchers

Watchers and Kibana alerting rules, incl. index-threshold and ES-query rules → Davis anomaly detectors + Workflows as upload-ready Settings JSON or Terraform.

Transforms

Continuous transforms → rollup DQL with a migration note per transform.

Cluster config

ILM policies, index templates and enrich policies → written guides for bucket retention, OpenPipeline routing and Grail lookups.

SLOs

Kibana SLO definitions → DQL SLI queries with the objective and window carried over, ready for the SLO app or API. APM indicators are flagged for the service-native path.

Shippers

Filebeat configs → OpenTelemetry Collector configs shipping straight to Dynatrace; Metricbeat modules are mapped to OneAgent and Extensions Hub advice.

Synthetic monitors

Heartbeat HTTP monitors → Dynatrace Synthetic monitor definitions; TCP and ICMP checks are flagged for network availability monitors.

AppD onboarding plan

Application/tier/node inventory → a OneAgent rollout sized by host. AppD needs an agent per process; OneAgent installs once per host and instruments everything on it — so the plan dedupes nodes to hosts, batches them into waves and carries the AppD identity across as host groups and tags.

AppD health rules

Static-threshold rules → Davis anomaly detectors with units rescaled (AppD reports milliseconds where Dynatrace uses microseconds). Baseline rules are reported as already covered by built-in Davis rather than converted — porting them would duplicate coverage and add noise.

AppD dashboards & actions

Custom dashboard widgets → DQL tiles with metric paths mapped to Grail keys; policies and actions → a notification plan. Diagnostic-capture actions are called out as needing no equivalent — Dynatrace captures continuously.

Every run also writes MIGRATION_REPORT.md with a deployment-order plan and a scorecard, plus a field manifest per dashboard (*.fields.md) listing what must exist at ingest or a tile renders empty. Elastic runs add METRICS-GUIDE.md for log→metric extraction, a CUTOVER-PLAN.md dual-ship schedule when ILM policies are present, and a suggested mapping.config.json when your index patterns need rules. AppDynamics runs add ONBOARDING-PLAN.md with the OneAgent rollout waves, plus waves.json and host_groups.json for driving an Ansible inventory.

Limitations

  • Maps and truly-custom Vega panels become placeholder tiles flagged MANUAL. Rebuild those by hand in Dynatrace.
  • Lens formulas with no DQL equivalent fall back to a flagged count() placeholder. Nothing is converted silently wrong.
  • A converted tile renders empty, with no error, when a custom field it queries isn't ingested in Dynatrace. Check each dashboard's .fields.md manifest before trusting a blank chart.
  • Index patterns without a mapping rule default to logs. Review the suggested mapping.config.json and re-run to make routing explicit.
  • Alert thresholds and evaluation windows are best-effort. Review each anomaly detector before enabling it in production.
  • Canvas workpads and ML jobs have no converter. Unrecognised files are listed as skipped, with a reason.
  • Converted AppD alerts and tiles are not entity-scoped. AppD scopes by application/tier/business-transaction name, and there is no reliable offline mapping to Dynatrace entities — a guessed filter would silently match nothing. Each one carries its original AppD scope as a note; add the filter before enabling.
  • The AppD dashboard widget schema is not publicly documented, so widgets are read defensively. Anything unrecognised becomes a placeholder tile naming the original widget type rather than disappearing.
  • AppD metric history cannot be backfilled. Dynatrace rejects metric data older than an hour, so any before/after comparison means running both stacks over the same window — budget a dual-run period per wave.
  • Dynatrace rejects log records older than 24 hours, so history cannot be replayed as-is. e2d backfill re-stamps it and keeps the true event time in original_timestamp; CUTOVER-PLAN.md schedules the dual-ship overlap instead.

Powered by the e2d engine compiled to WebAssembly (Pyodide). Conversion, DQL linting, field audits and the migration report all run locally in this tab; this page makes no network requests with your data.
